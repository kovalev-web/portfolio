# fraimye — сайт-портфолио

Главная, семь страниц кейсов и страница CV под паролем. Собран по мотивам
davidhaz.com — разбор референса в [REFERENCE.md](REFERENCE.md).

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
```

## Стек

React 19 + TypeScript + Vite, обычный CSS с custom properties, сырой WebGL
для градиентов. Из рантайм-зависимостей, кроме React, только `lucide-react` —
четыре иконки в шапке (`Menu`, `X`, `Moon`, `Sun`).

Прод-бандл: **80 KB gzip JS + 6 KB gzip CSS**.

## Деплой

Сайт отдаётся с **Vercel**, из проекта `portfolio`. Деплой — обычный пуш:

```bash
git push
```

Проект подключён к этому репозиторию, коммит в `main` собирается и выкатывается
в продакшн автоматически, за считанные секунды. Руками (`npx vercel deploy
--prod`) деплоить не нужно и лучше не стоит: ручные выкладки идут вперемешку с
автоматическими, и потом не разобрать, что откуда приехало.

> ⚠️ Домен привязан к **проекту**, а не к аккаунту, и имя проекта об этом ничего
> не говорит — до 29.07.2026 он назывался `cv`, по прошлому сайту. Прежде чем
> гадать, почему правки не видны на проде, надо спросить сам Vercel:
> `npx vercel domains inspect fraimye.com` печатает, за каким проектом закреплён
> домен. Сутки были потеряны ровно на этом: сайт деплоился на VPS, а домен вёл в
> пустой Vercel-проект, отдававший `DEPLOYMENT_NOT_FOUND`.

Канонический адрес — **`www.fraimye.com`**: Vercel редиректит апекс на www
(308). Редирект в обратную сторону добавлять нельзя — вместе с этим они
образуют бесконечную петлю.

**DNS**: домен куплен на reg.ru, зона ведётся в Cloudflare (NS делегированы на
`jimmy.ns.cloudflare.com` / `tori.ns.cloudflare.com`) — у reg.ru редактор
DNS-записей был заблокирован просроченным хостинг-планом. Записи домена:

| Тип | Имя | Значение | Proxy |
|---|---|---|---|
| CNAME | `@` | `fb3c50c6d7d0a458.vercel-dns-017.com` | DNS only |
| CNAME | `www` | то же | DNS only |

> ⚠️ **Оранжевое облако включать нельзя, пока режим SSL — `Flexible`.** Vercel
> редиректит HTTP на HTTPS, а Cloudflare во Flexible ходит на origin по HTTP:
> вместе это бесконечная петля. Понадобится проксирование — сначала `Full
> (strict)`, потом облако.

MX/SPF-записи (`mail`, `pop`, `smtp`, `ftp` → `31.31.198.2`) не трогали, хотя
почта на домене реально не настроена.

Промежуточный этап с раздачей статики с VPS `202.182.110.25` свёрнут: сайт
оттуда удалён, nginx-конфиг снят. На сервере остались другие проекты, к этому
репозиторию отношения не имеющие.

## Шапка: вырез и его филеты

Логотип живёт в вырезе, «прогрызенном» в углу hero-карточки. Шапка
`position: fixed`, и **сам вырез при скролле не меняется** — ровно как на
референсе, где `.header-logo-box` тоже фиксированный и залит цветом фона.
Состояния при скролле есть только у двух вещей рядом с ним: у филетов (ниже) и
у nav-пилюли (в конце раздела). На блок с аватаром и именем не должно влиять
ничего.

Заливка выреза непрозрачная (`var(--bg)`) на всех ширинах — именно она
не даёт логотипу столкнуться с заголовком секции, который проезжает под
ним. На мобильном вырез превращается в сплошную полосу на всю ширину, а
hero получает `padding-top: calc(var(--header-h) + 10px)`, чтобы полоса
не накрывала карточку.

> ⚠️ **На `.notch` нельзя вешать `border` — даже прозрачный.** При
> `box-sizing: border-box` бордер сдвигает padding-box, а вогнутые филеты
> позиционируются от него (`top: 100%`, `left: 100%`). Один пиксель бордера
> уводит оба филета из выравнивания и оставляет видимые полоски вдоль края
> карточки. То же относится к `.hero-copy` и его `::after`.

Оба филета сделаны на 1px больше со стороны, обращённой к сплошному блоку,
и на тот же 1px сдвинуты назад — сглаженный край радиального градиента
перекрывается сплошной заливкой и шва не остаётся. Окружность при этом
остаётся привязанной к углу бокса, так что дуга не меняется.

**Филеты видны только на самом верху** (`useAtTop` → `data-at-top`). Они
мостят вырез к краям карточки, а шапка фиксированная — карточка уезжает
из-под неё, и филеты повисают над ней чёрными клювами. На референсе ровно
та же проблема есть, просто её не видно: их nav-пилюля стоит вплотную к
логотипу и накрывает филет собой. Наша по макету улетела вправо, поэтому
филет оказывается голым на карточке.

Гаснут **только** эти две угловые фигуры. Сам блок с аватаром и именем не
меняется никогда — ни размера, ни формы, ни фона.

Nav-пилюля (`.nav-pill`) стеклянная — полупрозрачный блюр читается и на
синей карточке, и на любой секции ниже.

**Пилюля схлопывается в кружок** после 120px скролла и разворачивается обратно
у верха. Переключение по пересечению порога, а не на каждый тик: иначе
состояние переписывалось бы на любом движении колеса. Ширина считается
`scrollWidth`-ом в `useLayoutEffect` и ставится инлайном — анимировать `auto`
нельзя, а `scrollWidth` честно отдаёт полную ширину даже когда пилюля уже
визуально обрезана до круга, так что мерить можно в любом состоянии. Замер
повторяется по `document.fonts.ready`: на жёсткой перезагрузке шрифт может ещё
не приехать, и по узкому замеру пилюля обрезает `ThemeToggle`.

Клик по кружку — **подглядывание, а не режим**: кнопка `.nav-handle` вообще
существует только в схлопнутом состоянии, обратной кнопки нет. Развёрнутая
таким образом пилюля закрывается сама, как только страница уедет на 60px от
точки, где её открыли.

На мобильном вместо пилюли — шит (`.mobile-sheet`) по кнопке в вырезе; пока он
открыт, скролл `body` заблокирован, а клик по подложке закрывает меню нативным
слушателем в фазе перехвата, чтобы не просочиться в контент под ней.

Семь внутренних страниц, перенесённых со старого сайта. Каждая — плоский список
блоков в `cases.ts`; `CaseStudy.tsx` знает все их формы, так что добавить кейс

| Блок | Что рисует |
|---|---|
| `meta` | полоса Role / Platform / Focus |
| `lead` / `text` | вводный абзац и обычный |
| `eyebrow` / `heading` | надзаголовок и заголовок раздела |
| `goals` | нумерованный список с жирным зачином |
| `quote` | выноска с линией слева |
| `image` | кадр с подписью |
| `break` | воздух между главами |

**Тексты перенесены машинно.** `tools/import-cases.mjs` читает старые
`index.html` и перегенерирует `cases.ts` — проза это работа, а перепечатка
семи страниц вручную это способ незаметно изменить формулировки. Скрипт
односторонний: правки прямо в `cases.ts` перезапишутся. Запуск:

```bash
node tools/import-cases.mjs [путь-к-старому-сайту/projects]
```

Он же печатает отчёт по блокам — по нему сверялась полнота переноса.

Ничего своего по типографике и цвету страница не заводит: размеры из `--fs-*`,
цвет из `--ink`/`--ink-soft`/`--line`, радиусы и easing из общих токенов.
Единственное добавление в `base.css` — `--fs-h2`: в шкале не было ступени между
`--fs-lg` и дисплейными размерами, и заголовок раздела было нечем набрать.

Пути **`/projects/<slug>/`** оставлены как на старом сайте: они живые и
проиндексированы, ломать их незачем. Роутер — `hooks/useRoute.ts`,
`history.pushState` и одна подписка на `popstate`: столько страниц не оправдывают
библиотеку в проекте, который иначе везёт только React и четыре иконки.
Ссылки остаются настоящими `href` — копируются, открываются в новой вкладке и
индексируются, — а `onNavClick` перехватывает только простой левый клик.
`vercel.json` переписывает на `index.html` всё, кроме `/assets/` и `/media/`:
без этого прямой заход на кейс даёт 404. Неизвестный путь рисует `NotFound.tsx`
на стилях страницы кейса.

## Колода скринов в hero

Скрины лежат не в фиксированных слотах — это колода, по которой карточки
физически ездят. `heroDeck` в `content.ts` — плоское кольцо из всех скринов
всех проектов; крутится по одной карточке за шаг.

Каждая карточка колоды всегда смонтирована, и единственное, что меняется, —
атрибут `data-slot`, который `hero.css` превращает в трансформ. Слот это
геометрия, а не раскладка: только поэтому карточка может долететь из одного
слота в другой. Флекс так не умеет, и ровно из-за этого раскладка тут
абсолютная, а все карточки — одной формы (карточка не может менять пропорции
в полёте).

| Слот | Что это |
|---|---|
| `0` / `1` / `2` | веер: сдвиг влево-вниз и уменьшение вглубь, см. `--fan-*` ниже |
| `out-front` | ушла с переднего плана — вниз на всю высоту, за нижний край карточки |
| `hidden` | ждёт очереди: геометрия слота 2, но слоем ниже |

**Ничего никогда не становится полупрозрачным.** Это принцип, а не деталь: в
колоде карточки плотно перекрываются, и любая альфа на движущейся карточке
читается как призрак — сквозь неё видно ту, мимо которой она едет. Поэтому
прячут не прозрачностью, а перекрытием:

- Уезжающая проезжает **всю свою высоту** вниз и обрезается собственным
  `overflow: hidden` карточки hero. Она не растворяется — её просто больше нет
  в кадре.
- Ожидающая стоит ровно на геометрии слота 2, но `z-index` ниже, так что
  карточка слота 2 закрывает её пиксель в пиксель. Открывается она тем, что
  та уезжает вперёд, — как следующая карта в настоящей колоде.

Уход **наружу** заодно значит, что возвращающаяся в конец колоды карточка
никогда не летит сквозь стопку, так что `z-index` не приходится менять на лету
(а он и не анимируется). Обратный ход получается сам собой: при шаге назад
бывшая передняя карточка оказывается на `rel 1` и уезжает в середину веера, а
последняя ушедшая прилетает обратно.

### Перемотка точками — не то же самое, что шаг

Клик по точке перескакивает через несколько карточек сразу, и анимировать это
нельзя. Шаг на ±1 двигает ровно по одной карточке в каждый слот, а скачок —
сразу несколько, причём навстречу друг другу: карточки текущего веера
отъезжают назад в хвост, а карточки нового проекта выезжают вперёд оттуда же.
Пересечения читаются как посторонние слайды, ползущие сквозь колоду.

Ховер по точкам — **единственное**, что останавливает автопрокрутку курсором.
Сама колода не останавливает ничего: возить курсором по скринам и не морозить
их важнее. Помимо этого прокрутку глушит `prefers-reduced-motion` — там она не
теряет анимацию, а не запускается вовсе, потому что самопроизвольно едущий
контент и есть то, о чём эта настройка просит. Читается живьём, подпиской на
`change`: настройку можно переключить не перезагружая страницу. Точки при этом
работают, так что колода остаётся достижимой.

Сами точки — мишень 10×50px, для ховера этого мало, поэтому у `.hero-dots` есть
паддинг `--dots-hit` (14px) чисто под зону попадания: `right` отведён на ту же
величину, а в мобильном стеке паддинг гасится отрицательным `margin-block`, так
что сами точки не двигаются нигде.

Поэтому `jumped` в `Hero.tsx` (дельта не ±1) вешает `data-jump` на
`.hero-media`, а CSS снимает переход со всех карточек, **кроме** уезжающей
вперёд. Получается тот же одиночный жест, что и при автопрокрутке: передняя
карточка отрывается вниз, а новый веер уже стоит за ней. Атрибут снимается сам
на следующей смене индекса, так что автошаги после клика анимируются как
обычно.

> ⚠️ У `[data-slot="hidden"]` стоит `transition: none`, и это несущая
> деталь. Через это состояние карточки перескакивают из-под нижнего края обратно
> в хвост колоды — прыжок не должен рисоваться. Выход из `hidden` при этом
> анимируется нормально: переходом управляет тот стиль, **в который** переходят.

> ⚠️ Перекрытие работает только пока карточки непрозрачные — поэтому у
> `.hero-shot-placeholder` сплошная заливка, а не тонированная. Полупрозрачная
> заглушка вернёт призрака ровно там же.

### Ширина веера выводится, а не задаётся

Отступы слева и справа от колоды должны совпадать. Просто подобрать процент
сдвига для этого нельзя: карточки размерятся от **высоты** hero
(`aspect-ratio` от неё), а рамка, в которую они вписываются, — от его
**ширины**. Нужный сдвиг гуляет примерно от −64% до −108% на обычных
пропорциях десктопного окна, так что любая константа верна ровно при одной.

Поэтому `.hero-media` получает одинаковые `left`/`right` — коробка и есть то
место, которое колоде разрешено занимать, — и `container-type: inline-size`,
чтобы карточка изнутри могла измерить эту коробку:

```
--fan-travel: max(calc(var(--fan-s2) * 100% - 100cqw), calc(var(--fan-spread-max) * -100%))
```

`100%` — это карточка, `100cqw` — коробка. Первый аргумент кладёт левый край
задней карточки ровно на левый край коробки. Второй ограничивает разлёт: на
широком и невысоком окне точная посадка растащила бы карточки так, что они
перестали бы перекрываться, а колода без перекрытия — не колода.

Когда кап срабатывает, веер уже не заполняет коробку, и остаток нужно поделить
поровну — иначе он висит у правого края и весь зазор уходит влево, то есть
ровно тот перекос, ради которого всё это и считается. Этим занимается
`--fan-center`: половина остатка, и ноль, пока веер вписывается.

Проверено: 375×812, 1024×768, 1280×800, 1280×1100, 1440×900, 1920×950,
2560×1000 — отступы совпадают везде, перекрытие карточек от 21% до 76% ширины
в зависимости от пропорций окна.

На `≤860px` `.hero-card` становится колонкой (копия сверху, колода снизу),
коробка занимает всю ширину контента, а высота задаётся явно — она же решает,
насколько карточка уже коробки, то есть сколько у веера места на разлёт.
Скрывать задние карточки, как раньше, больше не нужно: их душил флекс, а
трансформам тесно не бывает.

## Анимации

**Blur-in на скролле.** Класс `.reveal` (`blur(12px) → 0`), для крупного текста
`.reveal-lg` (`blur(26px)`). Стаггер задаётся инлайн-переменной `--d`.
Один общий IntersectionObserver в `useReveal`, элемент раскрывается один раз.

**Ховеры.**

| Где | Что |
|---|---|
| Список работ | строка уезжает вправо, линия темнеет, соседние гаснут до 0.35, превью летит за курсором, курсор — SVG-стрелка (инвертируется в тёмной теме) |
| Опыт работы | строка уезжает вправо, соседние гаснут до 0.45, плюс превращается в минус поворотом на 180° |
| Скиллы ⏸ | медиа раскрывается по ховеру (не только по скроллу), соседние строки гаснут |
| Фото в About ⏸ | `scale(1.05)` |
| star-button | заливка инвертируется, ✦ мигают |

> ⚠️ `transition` — шорткат. Если элемент одновременно `.reveal` и имеет свой
> `transition`, свойства блюр-ина (`filter`, `opacity`, `transform`) надо
> перечислить в компонентном правиле, иначе они потеряются. Поэтому
> `base.css` импортируется **первым** — компонентные стили должны выигрывать.
> Так сделано в `.work-row`, `.scroll-cue`, `.star-button`.

## Где что править

**Контент.** Тексты и списки — в `src/data/content.ts`, компоненты трогать не
нужно. Опыт работы — массив `experience`, логотипы лежат в
`public/media/logos`; если файла нет, плитка покажет инициалы из поля
`initials`. Тексты кейсов — в `cases.ts`, но он **генерируется**, см. выше.

**Скрины в hero.** `public/media/project-{1,2,3}/{1,2,3}.webp`, пути перечислены
в `heroProjects` в `content.ts`. Кадр кропается по `object-fit: cover` от левого
верхнего угла, так что важен верх. Ратио карточки — `1306 / 1384` в
`.hero-media-card`; скрины другой формы — менять там, один раз на всю колоду.

**Обложки проектов** (превью за курсором в списке работ) —
`public/media/covers/<slug>.webp`, путь берётся из `cover` в `projects`. Все семь
смонтированы разом и переключаются по `data-active`: на одном `src` первая
наводка на каждую строку давала бы пустую плитку. Ратио плитки (`900 / 584`)
равно ратио обложек, поэтому `object-fit: cover` ничего не срезает; свои файлы
другой формы — менять и то и то.

**Палитра шейдера** — `SURFACE_PALETTE` в `webgl/GradientCanvas.tsx`: четыре hex,
одни на hero и на contact. Она общая намеренно — карточка должна читаться как
один медленно дышащий цвет, а не как радуга, и контактная секция должна
показывать ту же поверхность, а не второй несвязанный градиент.

**Плейсхолдеры-градиенты** остались только в `.about-media-fill` и
`.skill-media-fill` — обе секции запаркованы, так что на живом сайте их не видно.

## Что осталось

**Шрифт живёт на CDN.** Сейчас Mona Sans с Google Fonts — ближайшая бесплатная
замена Matter из референса. Стоит скачать `woff2`, положить в `public/fonts` и
убрать `<link>` из `index.html`: это снимает два `preconnect` к чужому домену с
критического пути и убирает замер по `document.fonts.ready` в шапке как класс
проблемы.

## Что ещё лежит в `<head>`

- **Бутстрап темы** — инлайновый скрипт, ставит `data-theme` на `<html>` до
  первой отрисовки, читая `localStorage`, а если там пусто — системную тему.
  Инлайновый и до бандла он именно поэтому: любой внешний файл здесь — гарантия
  вспышки не той темы.
- **Фавиконки под тему** — `favicon-light.png` / `favicon-dark.png` по
  `media="(prefers-color-scheme: …)"`, плюс `favicon.ico` без медиа-запроса как
  запасной для браузеров, которые эти два игнорируют.
- **Аналитика** — Umami, self-hosted на `analytics.screela.com` (тот же VPS, что
  и прочие проекты владельца), скрипт `defer`. Cookie-баннер не нужен: Umami не
  ставит куки и не собирает персональные данные.

## Заметки по производительности

- Шейдер — один полноэкранный треугольник, DPR ограничен 1.5.
- Рендер останавливается, когда карточка вне вьюпорта, когда вкладка в фоне
  и при `prefers-reduced-motion`.
- `preserveDrawingBuffer: true` нужен именно из-за остановки цикла: без него
  буфер очищается на следующем композите и карточка чернеет.
- Зерно рисуется 180×180 и растягивается CSS-ом, ~12 fps.
